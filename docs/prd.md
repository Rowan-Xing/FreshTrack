# 鲜知 FreshTrack 产品定义文档

## 0. 文档定位

本文档定义鲜知 FreshTrack 当前 Android PoC/MVP 的产品定位、目标用户、使用场景、功能范围、业务规则、交互状态和产品验收标准。

本文档只回答以下问题：

- 产品为谁服务、解决什么问题。
- 用户能够看到什么、完成什么操作。
- 各项功能遵循什么业务规则。
- 哪些结果代表产品行为符合定义。
- 哪些能力明确不属于当前范围。

本文档不记录技术选型、接口设计、数据存储方式、代码结构、测试执行结果、构建信息、发布步骤或项目进度。

除特别说明外，本文档中的“必须”“应”“不支持”均为当前 MVP 的确定产品规则。

## 1. 产品概述

### 1.1 产品定位

鲜知 FreshTrack 是一款面向个人用户的 Android 食品到期管理工具。

用户可以记录自己拥有的食品，按到期状态查看和筛选食品，在设备上接收到期提醒，并将食品标记为已吃完或已丢弃。产品保留处理历史，也允许用户将误处理的记录恢复为活动食品。

FreshTrack 的核心价值不是提供复杂的库存管理，而是用一个足够轻量、清楚且可持续使用的闭环，帮助用户：

1. 记住自己还有哪些食品。
2. 快速发现已经过期或即将到期的食品。
3. 在合适的日期和时间获得提醒。
4. 记录食品最终是被吃完还是被丢弃。
5. 通过持续记录减少遗忘和浪费。

### 1.2 待解决的问题

目标用户通常通过记忆、购物清单、冰箱摆放位置或临时便签管理食品，容易出现以下问题：

- 忘记已经购买或存放的食品。
- 无法快速判断哪些食品应优先处理。
- 到期日分散，缺少统一视图。
- 普通日历提醒与具体食品记录脱节，维护成本高。
- 食品被吃完或丢弃后缺少简单的处理记录。
- 多个账号在同一设备上使用时，食品和提醒容易产生混淆。

### 1.3 产品原则

- 个人优先：当前产品服务单个账号下的个人食品，不承担家庭共享或商业库存管理。
- 状态清楚：食品状态必须通过文字明确表达，不能只依赖颜色。
- 用户主动：权限申请、删除、吃完、丢弃和恢复等关键行为均由用户明确触发。
- 日历日期优先：到期日表示设备本地日历中的某一天，不表示一个精确到小时的保质期限。
- 提醒不阻断业务：通知权限或提醒同步失败不能阻止用户管理食品。
- 数据按账号隔离：用户只能看到和操作当前账号的数据。
- 结果可恢复：临时网络失败应允许重试；只有用户确认的永久删除不可恢复。

## 2. 目标用户与核心场景

### 2.1 目标用户

主要目标用户是：

- 使用 Android 手机的个人用户。
- 希望记录少量到中等数量日常食品的用户。
- 关注食品到期时间，但不需要复杂仓储、采购或成本管理的用户。
- 愿意使用邮箱和密码创建个人账号的用户。
- 希望通过本机提醒减少遗忘的用户。

当前 MVP 不以餐饮门店、仓库、零售商、多人家庭协作或专业营养管理为目标。

### 2.2 核心使用场景

#### 场景 A：购买或整理食品后录入

用户在购物、整理冰箱或收纳食品后，记录食品名称、分类、数量、单位、到期日、提醒开关和可选备注。

#### 场景 B：每天查看应优先处理的食品

用户打开首页，通过“已过期”“今天到期”“未来 1–3 天”概览和排序，快速找到近期需要处理的食品。

#### 场景 C：按名称或分类寻找食品

用户通过名称搜索、分类筛选和到期分段组合缩小列表范围。

#### 场景 D：记录食品处理结果

用户将活动食品标记为已吃完或已丢弃。食品离开活动列表并进入历史记录。

#### 场景 E：纠正误操作

用户从历史详情中恢复误标记的食品，使其重新回到活动列表，并继续沿用原有食品信息和到期日。

#### 场景 F：获得本地到期提醒

用户主动允许通知，设置提前天数和提醒时间。符合条件的活动食品在本机指定时间产生通知。

#### 场景 G：更换账号或重新打开应用

用户退出后使用其他账号登录，或关闭应用后再次打开。产品只展示当前账号数据，并在登录状态仍有效时恢复使用状态。

## 3. 产品目标与成功标准

### 3.1 当前 MVP 目标

1. 建立从注册登录、食品录入、到期查看、提醒、处理到历史恢复的完整闭环。
2. 让用户无需逐条打开详情，也能识别过期、今天到期和未来三天内到期的食品。
3. 让本地提醒始终服从当前账号、当前食品状态和当前提醒设置。
4. 保证不同账号的食品、历史和提醒偏好相互隔离。
5. 在网络、登录状态或通知权限发生异常时，向用户提供明确反馈和可执行的恢复路径。

### 3.2 产品成功判定

当前 PoC/MVP 不以增长、留存或商业转化指标作为验收依据。满足以下用户结果，即认为产品定义闭环成立：

- 新用户可以注册并立即开始记录食品。
- 已登录用户可以在重新打开应用后继续管理自己的食品。
- 用户可以准确找到已过期、今天到期和未来 1–3 天到期的食品。
- 用户可以完成食品新增、查看、编辑、吃完、丢弃、恢复和永久删除。
- 用户允许通知后，可以按照账号设置收到仍然有效的本地提醒。
- 用户拒绝通知或遇到提醒失败时，食品管理功能仍然可用。
- 两个账号不会看到、修改或继承彼此的食品、历史和提醒设置。

## 4. 产品形态与使用约束

### 4.1 平台与语言

- 当前产品只提供 Android 手机应用。
- 当前产品界面语言为简体中文。
- 主要使用形态为 Android 手机竖屏。
- 界面应适配约 360–412 dp 的常见手机内容宽度。
- 当前 MVP 不专门适配平板、大屏设备或横屏布局。

### 4.2 网络与设备条件

- 注册、登录、读取食品、修改食品和退出登录需要可用网络。
- 当前 MVP 不提供完整的离线浏览、离线新增或离线编辑能力。
- 已经成功安排在本机的提醒不依赖持续联网即可由设备触发。
- 本地提醒依赖设备通知权限、系统时间、日历日期和本地时区。

### 4.3 账号数据与设备数据

- 食品和处理历史属于账号。用户在同一账号重新登录后，应继续看到该账号已有数据。
- 提醒权限、提醒偏好和已安排提醒属于当前设备，不在不同设备之间同步。
- 同一账号在新设备或重新安装后，食品数据仍属于该账号，但该设备上的提醒偏好恢复为默认值，并需要重新取得通知权限。
- 同一账号再次登录同一设备时，沿用该账号此前在本机成功保存的提醒偏好；退出登录只取消已安排提醒，不删除提醒偏好。
- 一个设备可以先后登录不同账号，但每个账号的提醒偏好必须独立。

## 5. 信息架构与导航

### 5.1 页面结构

| 区域 | 页面 | 主要职责 |
| --- | --- | --- |
| 启动 | 登录状态恢复页 | 判断用户应进入认证区域还是已登录区域；失败时提供重试 |
| 认证 | 登录页 | 使用邮箱和密码进入已有账号 |
| 认证 | 注册页 | 创建账号并直接进入已登录区域 |
| 主导航 | 首页 | 查看活动食品、到期概览、搜索筛选、排序和快捷操作 |
| 主导航 | 历史 | 查看已吃完和已丢弃食品，搜索、筛选并进入详情 |
| 主导航 | 设置 | 查看当前账号、管理通知权限和提醒偏好、退出登录 |
| 次级页面 | 新增食品 | 创建一项活动食品 |
| 次级页面 | 食品详情 | 查看完整信息并执行当前状态允许的操作 |
| 次级页面 | 编辑食品 | 修改活动食品 |

### 5.2 主导航

登录后底部固定提供三个入口：

1. 首页。
2. 历史。
3. 设置。

新增、详情和编辑从主导航之上进入。用户完成操作或主动返回后，回到此前页面。

### 5.3 核心状态流转

1. 首次启动且无有效登录状态：启动页 → 登录或注册。
2. 注册成功：注册页 → 首页。
3. 已有有效登录状态：启动页 → 首页。
4. 新增食品：首页 → 新增 → 首页。
5. 编辑食品：首页或详情 → 编辑 → 前一页面。
6. 处理食品：活动食品 → 已吃完或已丢弃；该食品随后归入历史。
7. 恢复食品：历史详情 → 活动状态；该食品随后重新出现在首页。
8. 退出成功：设置 → 登录页。

## 6. 账号与登录状态

### 6.1 注册

- 注册需要邮箱和密码。
- 邮箱必须是有效邮箱格式，去除首尾空格后不得为空，最长 254 个字符。
- 邮箱不区分字母大小写；例如 `Name@Example.com` 与 `name@example.com` 视为同一邮箱。
- 同一标准化邮箱只能注册一个账号。
- 密码长度必须为 8–128 个字符。
- 当前 MVP 不额外强制大小写字母、数字或特殊字符组合，但界面应提示用户使用不易猜测的密码。
- 注册成功后自动登录，不要求用户再次输入凭据。
- 邮箱已注册时，应在邮箱字段附近明确提示“该邮箱已注册”。
- 字段格式错误、网络错误和其他注册失败必须分别提供可理解反馈。

### 6.2 登录

- 登录使用注册邮箱和密码。
- 邮箱在登录时同样去除首尾空格并忽略字母大小写。
- 邮箱或密码不匹配时，统一提示“邮箱或密码错误”，不暴露具体是哪一项错误。
- 登录提交期间按钮显示加载状态，并阻止重复提交。
- 登录成功后进入首页。

### 6.3 登录状态恢复

- 注册或登录产生的登录状态默认自创建起有效 30 天，不因日常使用自动延长。
- 应用启动时先显示确定的恢复状态，不能短暂闪现错误账号或认证页面。
- 本机没有登录状态时，进入登录页。
- 登录状态有效时，恢复当前账号并进入已登录区域。
- 登录状态已过期或确定无效时，清理当前登录状态，停止该账号在本机的提醒，并进入登录页。
- 暂时无法联网或暂时无法验证登录状态时，不得直接认定账号失效；启动页显示错误和“重新连接”入口。
- 应用从后台回到前台时，如确定登录状态已失效，应退出当前账号；普通网络失败不应自动退出。

### 6.4 退出登录

- 设置页提供“退出登录”。
- 退出成功只结束当前设备上的本次登录，不影响同一账号在其他设备或其他有效登录中的使用。
- 退出成功后清除当前账号在本机安排的提醒，并进入登录页。
- 如果普通网络错误导致退出失败，用户继续保持登录，食品和提醒状态不被静默清除，并可再次尝试退出。
- 退出提交期间阻止重复点击。

### 6.5 账号隔离

- 当前账号只能查看和操作自己的食品、概览计数和历史。
- 当前账号尝试打开其他账号食品时，应得到与食品不存在一致的结果，不能获知该食品是否真实存在。
- 账号切换后，旧账号的列表、详情、筛选结果和操作结果不得出现在新账号界面中。
- 提醒偏好和提醒处理必须按账号隔离；一个账号的设置不能覆盖另一个账号的设置。

## 7. 食品模型与业务规则

### 7.1 食品字段

| 字段 | 是否必填 | 新增默认值 | 产品规则 |
| --- | --- | --- | --- |
| 食品名称 | 是 | 空 | 去除首尾空格后为 1–100 个字符；允许不同食品使用相同名称 |
| 分类 | 是 | 蔬菜水果 | 必须从固定分类中选择 |
| 数量 | 是 | 空 | 必须大于 0；最多三位小数；整数部分最多 15 位 |
| 单位 | 是 | 克 | 可选内置单位，也可输入最长 20 个字符的自定义单位 |
| 到期日期 | 是 | 设备当天日期 | 必须是真实存在的本地日历日期；允许选择过去、今天或未来日期 |
| 单食品提醒 | 是 | 开启 | 决定该食品是否参与当前账号的本地提醒 |
| 备注 | 否 | 无 | 去除首尾空格后最多 500 个字符；空内容视为无备注 |

数量保存后以简洁十进制形式展示：

- 无意义的前导零会被移除。
- 小数末尾无意义的零会被移除。
- 例如 `001.500` 展示为 `1.5`。

### 7.2 固定分类

食品分类固定为：

1. 蔬菜水果。
2. 肉蛋水产。
3. 乳制品。
4. 主食粮油。
5. 零食饮料。
6. 调味品。
7. 其他。

### 7.3 内置单位

内置单位为：

- 克。
- 千克。
- 毫升。
- 升。
- 个。
- 盒。
- 袋。
- 瓶。
- 罐。
- 份。

选择“自定义单位”后，用户必须填写非空单位。自定义单位去除首尾空格后最长 20 个字符。

### 7.4 食品生命周期状态

食品只有以下三种业务状态：

| 状态 | 含义 | 允许操作 |
| --- | --- | --- |
| 活动 | 用户当前仍拥有或仍需处理的食品 | 查看、编辑、标记已吃完、标记已丢弃、删除 |
| 已吃完 | 用户确认食品已经吃完 | 查看、恢复为活动食品、删除 |
| 已丢弃 | 用户确认食品已经丢弃 | 查看、恢复为活动食品、删除 |

状态规则：

- 新增成功的食品始终进入“活动”状态。
- 到期日期变化不会自动把食品变为已吃完或已丢弃；过期食品仍然是活动食品，直到用户主动处理或删除。
- 活动食品只能被处理一次。处理成功后记录实际处理时间。
- 已处理食品不能编辑，也不能再次标记为已吃完或已丢弃。
- 只有已吃完或已丢弃食品可以恢复。
- 恢复后状态变为活动，处理时间被移除。
- 恢复保留原名称、分类、数量、单位、到期日、单食品提醒和备注。
- 恢复不视为重新新增；“最近添加”仍按原创建时间排序。
- 删除适用于活动食品和历史食品。删除成功后记录永久消失，无法恢复。

## 8. 到期日期与展示规则

### 8.1 日期口径

- 到期日只表示设备本地日历日期，统一展示为 `YYYY-MM-DD`。
- “今天”取设备当前本地日期。
- 日期判断按日历日期进行，不按已经经过多少小时判断。
- 跨月、跨年和夏令时变化不能改变某个食品所属的日历日期分段。

### 8.2 到期分段

对活动食品定义四个首页概览：

| 分段 | 定义 |
| --- | --- |
| 全部 | 当前账号的全部活动食品 |
| 已过期 | 到期日早于今天 |
| 今天到期 | 到期日等于今天 |
| 未来 1–3 天 | 到期日在明天至今天之后第 3 天之间，包含两端 |

“已过期”“今天到期”“未来 1–3 天”三个日期分段互不重叠。到期日在三天之后的活动食品只计入“全部”，因此三个日期分段数量之和不一定等于全部数量。

### 8.3 食品卡状态文案

活动食品卡根据到期日显示：

- 早于今天：已过期。
- 等于今天：今天到期。
- 明天至三天后：1–3 天内。
- 三天之后：新鲜。

历史食品卡不再展示新鲜度状态，而是展示“已吃完”或“已丢弃”。

## 9. 首页

### 9.1 首页内容

首页包含：

- 当前设备日期。
- 新增食品入口。
- 全部、已过期、今天到期、未来 1–3 天四个概览卡。
- 名称搜索。
- 到期分段筛选。
- 分类筛选。
- 排序选择。
- 清除筛选入口。
- 活动食品列表。
- 下拉刷新和继续加载。

### 9.2 概览与筛选联动

- 概览数量统计当前账号的全部活动食品，不受名称搜索、分类筛选或当前排序影响。
- 点击“全部”只清除到期分段，保留名称搜索、分类和排序。
- 点击其他概览卡应用对应到期分段，保留名称搜索、分类和排序。
- 概览加载失败时，首页明确提示概览暂时不可用，并允许单独重试；食品列表仍可继续使用。

### 9.3 名称搜索

- 搜索只匹配食品名称。
- 搜索词去除首尾空格后参与匹配。
- 搜索采用包含匹配，不要求从名称开头匹配。
- 英文字母匹配不区分大小写。
- 搜索词最长 100 个字符。
- 空搜索词等同于未搜索。

### 9.4 组合筛选

- 首页支持名称搜索、到期分段和分类同时生效。
- 多个条件之间采用“同时满足”的关系。
- 分类可以选择“全部分类”或任一固定分类。
- “清除筛选”清空名称搜索、分类和到期分段，但保留用户当前选择的排序方式。
- 只有名称搜索、分类或到期分段实际生效时才显示“清除筛选”。

### 9.5 排序

首页提供两种排序：

1. 到期优先：到期日越早越靠前；到期日相同时，较晚添加的食品靠前。
2. 最近添加：较晚添加的食品靠前。

默认使用“到期优先”。相同排序条件下列表顺序必须保持确定，刷新后不应无故跳动。

### 9.6 食品卡

每张活动食品卡至少显示：

- 食品名称。
- 数量和单位。
- 分类。
- 到期日期。
- 到期状态文字。
- 进入详情入口。
- 快捷操作入口。

食品名称过长时允许在卡片中截断，但不能挤压或遮挡主要操作；用户仍可在编辑页查看原有完整内容。

### 9.7 卡片操作

活动食品卡提供两条路径：

1. 点击卡片主体进入详情。
2. 点击快捷操作入口，选择编辑、标记已吃完、标记已丢弃或删除。

编辑直接进入编辑页。吃完、丢弃和删除必须先二次确认。

### 9.8 列表状态

- 首次进入显示明确的加载状态。
- 无任何活动食品时，提示用户通过“新增”记录第一份食品。
- 有筛选但无匹配结果时，提示用户清除筛选或更换搜索词。
- 首屏加载失败时，显示错误说明和重新加载入口。
- 用户可以下拉刷新列表和概览。
- 列表按批加载，首批及每次继续加载最多 50 项。
- 存在后续数据时显示“加载更多”。
- 后续加载失败只影响后续数据，已显示内容保留，并提供“重试加载更多”。
- 已到末页时不再显示加载更多入口。
- 页面显示当前已经加载的食品数量，但该数字不替代“全部”概览。

## 10. 新增、编辑与详情

### 10.1 新增食品

- 新增页使用第 7.1 节定义的字段和默认值。
- 食品名称、分类、数量、单位和到期日期必须填写。
- 单食品提醒默认开启，但是否实际产生通知仍取决于权限、全局设置、食品状态和触发时间。
- 用户可以录入已经过期的食品；保存后该食品作为活动食品显示在“已过期”分段。
- 用户可以录入同名食品，系统不自动合并。
- 字段错误应尽量显示在对应字段附近。
- 提交失败时保留用户已经输入的内容，并提供可理解的错误信息。
- 提交期间显示加载状态并阻止重复提交。
- 只有新增成功后才生成食品记录；直接返回不保存草稿。
- 新增成功后返回前一页面并更新相关列表、概览和提醒。

### 10.2 编辑食品

- 只有活动食品可以编辑。
- 编辑页带入食品当前全部可编辑字段。
- 用户可以修改名称、分类、数量、单位、到期日期、单食品提醒和备注。
- 保存修改使用与新增相同的字段校验规则。
- 编辑不会改变食品的原创建时间。
- 保存成功后更新详情、列表、概览和提醒。
- 保存失败时保留当前输入，原有已保存记录不被当作修改成功。
- 未保存直接返回时，不改变原记录，也不保存草稿。

### 10.3 食品详情

详情页至少展示：

- 食品名称。
- 当前状态或到期状态。
- 分类。
- 数量和单位。
- 到期日期。
- 单食品提醒是否开启。
- 备注；没有备注时显示“无”。
- 已处理食品的处理时间。

活动食品详情提供：

- 编辑。
- 标记已吃完。
- 标记已丢弃。
- 删除食品。

历史食品详情提供：

- 恢复为活动食品。
- 删除历史记录。

详情加载失败时显示重试入口。食品已被删除、无权访问或不存在时，统一显示食品不存在，不暴露其他账号信息。

### 10.4 操作确认与反馈

以下操作必须二次确认：

- 删除活动食品。
- 删除历史记录。
- 标记已吃完。
- 标记已丢弃。
- 恢复为活动食品。

确认信息必须说明主要后果：

- 删除后无法恢复。
- 吃完或丢弃后食品进入处理历史。
- 恢复后保留原食品内容和原到期日。

操作提交期间：

- 禁止重复提交同一操作。
- 禁止通过连续点击同时触发多个互斥状态变化。
- 成功后提供明确反馈并刷新受影响页面。
- 失败后保留当前可理解状态，显示错误并允许重试。

食品操作成功但提醒处理失败时，食品操作结果仍然生效；界面额外显示提醒警告和重试路径。

## 11. 历史

### 11.1 历史范围

历史只包含当前账号中：

- 已吃完食品。
- 已丢弃食品。

活动食品不出现在历史中。历史记录一直保留，直到用户恢复或永久删除。

### 11.2 搜索与筛选

- 历史支持按食品名称搜索。
- 搜索规则与首页名称搜索一致。
- 历史状态筛选包括“全部”“已吃完”“已丢弃”。
- 搜索和状态筛选可以同时生效，结果必须同时满足两个条件。

### 11.3 排序与展示

- 历史默认按处理时间从近到远排序。
- 每张历史食品卡显示食品名称、数量、单位、分类、原到期日和处理状态。
- 点击历史卡进入详情。
- 历史详情显示处理时间，并允许恢复或永久删除。

### 11.4 恢复

- 恢复必须经过二次确认。
- 恢复成功后食品从历史消失并重新进入活动列表。
- 恢复保留原到期日；如果原到期日早于今天，恢复后立即显示为已过期。
- 恢复保留原单食品提醒开关，并按照当前设备、当前账号的提醒条件重新判断是否安排通知。
- 如果对应提醒时间已经错过，不补发提醒。

### 11.5 历史列表状态

- 首次进入显示加载状态。
- 没有处理记录时，说明吃完或丢弃的食品会出现在这里。
- 有筛选但无匹配结果时，提示更换搜索词或状态筛选。
- 首屏失败提供重新加载。
- 支持下拉刷新。
- 历史按批加载，首批及每次继续加载最多 50 项。
- 后续加载失败时保留已显示内容，并允许单独重试。

## 12. Android 本地提醒

### 12.1 提醒性质

- 当前产品只提供 Android 设备本地通知。
- 提醒由当前设备安排，不在多个设备之间同步。
- 当前产品不依赖远程推送。
- 当前产品不通过常驻或周期后台任务持续扫描食品。
- 已成功安排的本地提醒可以在设备暂时离线时触发。

### 12.2 通知权限

设置页显示三种权限状态：

| 状态 | 产品行为 |
| --- | --- |
| 未询问 | 应用不自动弹出系统请求；显示“允许本地通知”入口 |
| 已允许 | 符合全部条件的食品可以安排本地通知 |
| 已拒绝 | 不重复弹出权限请求；提供进入 Android 应用设置的入口 |

权限规则：

- 只有用户主动点击“允许本地通知”时，应用才请求系统权限。
- 用户拒绝权限后，食品新增、编辑、查看和处理仍然可用。
- 用户从系统设置修改权限并返回应用后，应用重新读取权限并校准提醒。
- 权限被关闭后，应用不应继续保留当前账号已知的有效提醒计划。

### 12.3 提醒设置

每个账号在每台设备上拥有独立设置：

| 设置 | 可选值 | 默认值 |
| --- | --- | --- |
| 全局提醒 | 开启或关闭 | 开启 |
| 提前天数 | 到期当天、提前 1 天、提前 2 天、提前 3 天 | 提前 1 天 |
| 提醒时间 | 00:00–23:59，精确到分钟 | 09:00 |

设置规则：

- 设置页显示当前账号邮箱和当前生效的提醒设置。
- 修改设置后，只有点击“保存并重排提醒”且保存成功，新的设置才正式生效。
- 关闭全局提醒并保存后，取消当前账号在本机已安排的全部食品提醒。
- 再次开启并保存后，重新判断所有活动食品是否满足提醒条件。
- 新账号、新设备或重新安装后的设备使用默认设置。
- 同一账号再次登录同一设备时，读取该账号此前成功保存的设置。
- 如果设备上保存的提醒设置无法识别，产品恢复为默认设置，并以默认值继续展示。
- 一个账号的设置变化不得影响其他账号。

### 12.4 触发时间

提醒触发时间按以下规则确定：

> 食品到期日减去提前天数，再与设置中的提醒时间组合，使用设备当前本地日历和本地时区。

示例：

- 到期日为 `2026-08-10`，提前 1 天，时间为 `09:00`，则计划在设备本地时间 `2026-08-09 09:00` 提醒。
- 到期日为当天，提前 0 天，时间为 `18:30`，只有当前时间早于 `18:30` 才安排提醒。

### 12.5 安排提醒的必要条件

一项食品只有同时满足以下条件才保留提醒：

1. 系统通知权限为已允许。
2. 当前账号全局提醒已开启。
3. 该食品的单食品提醒已开启。
4. 食品状态为活动。
5. 计算出的触发时间严格晚于当前时间。

任一条件不满足时，不安排提醒，并取消该食品此前由 FreshTrack 安排的旧提醒。

已经错过或恰好等于当前时刻的提醒不补发。过期食品仍可保留在活动列表中，但如果其提醒时刻已经过去，不会产生迟到通知。

### 12.6 通知内容与打开行为

每项符合条件的食品分别安排通知。通知内容为：

- 标题：`{食品名称} 即将到期`
- 正文：`{食品名称} 的到期日是 {YYYY-MM-DD}`

多个食品触发时间相同时，FreshTrack 分别产生通知，最终排列和分组方式由 Android 系统决定。

点击通知应打开 FreshTrack。当前 MVP 不保证直接进入对应食品详情页。

### 12.7 提醒校准时机

- 新增食品成功后，判断并安排该食品提醒。
- 编辑食品成功后，取消不再有效的旧计划，并按新内容重新判断。
- 恢复食品成功后，按原食品信息和当前设置重新判断。
- 删除、标记已吃完或标记已丢弃成功后，取消该食品提醒。
- 提醒设置保存成功后，重新判断当前账号全部活动食品。
- 应用启动、恢复有效登录状态和从后台回到前台时，重新读取权限并校准当前账号提醒。
- 设备日期、时间或时区发生变化后，在应用下一次启动或回到前台时按新环境重新校准。
- 因为当前 MVP 不执行周期后台扫描，所以应用未被重新打开或唤回前台前，不承诺立即发现其他设备上的食品变化或系统环境变化。

### 12.8 提醒失败与账号切换

- 提醒失败不能回滚已经成功的食品新增、编辑、恢复、删除、吃完或丢弃。
- 食品操作成功但提醒失败时，显示“食品操作已完成”的结果，同时显示可理解的提醒警告。
- 设置未能保存时，明确提示设置未保存，原有效设置保持不变。
- 设置已保存但部分提醒未能更新时，明确说明设置已保存，并提供“重新同步全部提醒”。
- 成功退出或确定登录状态失效后，只清理对应账号在本机的提醒。
- 普通退出网络失败时保持登录，也保留该账号现有提醒。
- 登录其他账号后，不读取、显示或覆盖前一账号的提醒设置。

## 13. 通用页面状态与异常处理

### 13.1 必须覆盖的页面状态

首页、历史、详情、设置和表单根据各自功能，应覆盖：

- 首次加载。
- 加载成功。
- 无数据。
- 有筛选但无匹配结果。
- 首次加载失败。
- 下拉刷新。
- 后续内容加载中。
- 后续内容加载失败。
- 提交中。
- 提交成功。
- 字段校验失败。
- 网络或服务失败。
- 登录状态失效。
- 提醒保存失败。
- 提醒同步警告。

### 13.2 错误处理原则

- 错误信息使用用户可以理解的语言，不展示内部实现信息。
- 可以重试的失败必须提供明确重试入口。
- 首屏失败与后续加载失败分开处理；后续失败不得清空已经显示的数据。
- 概览失败不得阻断食品列表。
- 通知失败不得阻断食品管理。
- 普通网络失败不得静默清除潜在有效的登录状态。
- 确定登录状态无效时，应退出并防止继续展示受保护数据。
- 账号、登录状态或筛选条件变化后，旧结果不得覆盖当前界面。

### 13.3 表单与操作状态

- 表单在字段失焦或提交时展示校验错误。
- 服务返回的字段错误应尽量归属到对应字段。
- 无法归属到单一字段的错误显示在表单级错误区域。
- 提交时显示加载反馈并禁用重复提交。
- 键盘不得遮挡当前输入字段或主要提交按钮。
- 页面内容超出屏幕时必须可以滚动。
- 快速连续点击不得造成重复记录或相互冲突的状态变化。

## 14. 视觉、交互与无障碍

### 14.1 视觉方向

- 主色使用蔬菜绿。
- 主要内容表面使用白色和极浅绿色。
- 危险、警告、成功和普通状态具有清晰区分。
- 到期、处理和错误状态必须同时提供文字，不能只通过颜色表达。
- 页面层级应保持简洁，突出食品名称、到期日、状态和主要操作。

### 14.2 交互要求

- 主导航保持稳定，用户可在首页、历史和设置之间直接切换。
- 新增、详情和编辑使用明确的返回路径。
- 破坏性操作和状态转换使用确认弹层。
- 加载中的按钮不可再次触发。
- 列表、筛选、弹层和状态切换可以使用短而克制的过渡。
- 系统开启“减少动态效果”时，应减少或取消非必要动画。
- 键盘、安全区、滚动和弹层不得遮挡关键内容。
- 长名称、长单位和长备注不得破坏页面布局。

### 14.3 无障碍要求

- 仅图标按钮必须具有可读的操作名称。
- 选中的筛选项和导航项必须能够被识别为选中状态。
- 错误和重要警告应以可感知方式呈现。
- 交互控件应具有足够的点击区域。
- 文本缩放后，主要字段、状态和操作仍应可阅读和使用。

## 15. 产品验收标准

本节定义用户视角的产品行为，不记录测试过程或执行结果。

### 15.1 账号闭环

1. 无登录状态启动应用时，用户最终进入登录或注册区域。
2. 用户使用有效邮箱和 8–128 位密码可以注册，并在成功后直接进入首页。
3. 重复邮箱注册得到明确提示，且不会创建第二个账号。
4. 邮箱或密码错误时，登录失败且不暴露具体错误项。
5. 有效登录状态在重新打开应用后可以恢复。
6. 暂时无法联网时，恢复页提供重试且不会直接删除登录状态。
7. 确定登录状态已过期后，用户回到登录页，对应账号本机提醒被清理。
8. 普通网络错误导致退出失败时，用户仍保持登录。
9. 退出成功只结束当前登录，不影响同账号的其他有效登录。

### 15.2 食品完整生命周期

1. 用户可以按默认值进入新增页，并填写所有必填字段。
2. 无效数量、空名称、空单位、无效日期和超长内容不能提交。
3. 用户可以添加同名食品，也可以添加到期日早于今天的食品。
4. 新增成功后，食品出现在活动列表和正确概览分段。
5. 用户可以查看活动食品详情并修改全部可编辑字段。
6. 编辑成功后，详情、列表、概览和提醒规则使用新内容。
7. 用户确认吃完或丢弃后，食品从活动列表进入对应历史状态。
8. 已处理食品不能编辑或再次处理。
9. 用户确认恢复后，食品回到活动列表，保留原内容和到期日。
10. 用户确认永久删除后，食品不再出现在活动列表、历史或详情中。

### 15.3 首页与历史

1. 四个概览数量符合第 8.2 节定义。
2. 点击概览卡只改变到期分段，不清除名称、分类或排序条件。
3. 名称搜索、到期分段和分类筛选能够组合生效。
4. 清除筛选会清空搜索、分类和到期分段，但保留排序。
5. “到期优先”和“最近添加”按照第 9.5 节排序。
6. 首页卡片可以进入详情，也可以打开快捷操作。
7. 历史只显示已吃完和已丢弃食品，并按处理时间从近到远排列。
8. 首页和历史在空库、无筛选结果、首屏失败及后续加载失败时显示不同且正确的状态。
9. 超过首批数量的食品可以通过“加载更多”继续查看，不重复、不遗漏已返回记录。

### 15.4 本地提醒

1. 全新安装时应用不会自行弹出通知权限请求。
2. 用户主动允许后，未来触发时间的合格食品可以收到通知。
3. 通知标题、正文、食品名称和到期日符合第 12.6 节。
4. 用户拒绝权限后仍能使用全部食品管理功能，且应用不反复请求。
5. 关闭单食品提醒会取消该食品提醒，不影响其他食品。
6. 关闭全局提醒并保存后，取消当前账号全部食品提醒。
7. 修改提前天数、提醒时间或到期日并保存后，旧计划不再保留，按新条件安排。
8. 吃完、丢弃或删除后，对应食品不再产生提醒。
9. 恢复食品后，只在新的计算时刻仍处于未来时安排提醒。
10. 已经错过的提醒不会补发。
11. 食品操作成功但提醒失败时，食品结果保留，并出现可重试警告。
12. 不同账号的提醒设置和提醒计划互不覆盖。

### 15.5 隔离、异常与可用性

1. 账号 A 无法查看或操作账号 B 的食品，也无法判断目标是否属于账号 B。
2. 账号切换后，旧账号数据和迟到结果不会出现在新账号界面。
3. 首屏、概览、分页、表单和提醒错误均具有可理解反馈。
4. 可重试错误提供明确入口，局部错误不清除已经成功显示的数据。
5. 连续点击不会创建重复食品或重复执行吃完、丢弃、恢复、删除和退出。
6. 常见 Android 手机宽度下，键盘、安全区、长文本和弹层不阻断主要流程。
7. 到期和处理状态不用颜色也能被识别。
8. 开启减少动态效果后，用户仍能完整操作所有功能。

## 16. 明确不在当前范围

当前 MVP 不包含：

- iOS 应用。
- 平板或横屏专项适配。
- 应用商店正式发布。
- 远程推送。
- 常驻或周期后台扫描。
- 跨设备同步提醒权限、提醒偏好或本地提醒计划。
- 完整离线浏览、离线新增或离线编辑。
- 通知快捷操作、通知聚合规则或保证点击后直达食品详情。
- 食品图片。
- 条形码或二维码扫描。
- AI 图像识别、保质期识别或智能推荐。
- 邮箱验证。
- 找回密码或修改密码。
- 第三方账号登录。
- 注销账号。
- 数据导入、导出或备份工具。
- 家庭成员、多人协作或共享食品库。
- Web 管理后台。
- 商业库存、采购、成本或营养分析。
- 支付、订阅或广告。
